## 3. Controller
**Mapped (data):**
* Move: left stick (Input Manager `Horizontal / Vertical`), Run: L3 hold (`controls.json bindings run`).
* Strike RB (tap light, hold heavy), direction from the right stick flick (overhead, thrust, slash L / R), Guard LB, guard side by right stick (`controls.json pad`, `guardLatch true`), Dodge A, Riposte B, Special 1 Y, Special 2 X, Lock R3, Kick D-pad up, Feint D-pad down, Stance D-pad left / right, Potion cycle LB + D-pad up, Recenter LB + D-pad down, Potion use Back (`PotionCfg.cs:36`), free look right stick when not locked (`pad_extras.json`, axes `RightStickX/Y`, `DPadX/Y` exist in InputManager.asset), Pause Start.
* Menu by pad: left stick up / down, A confirm, B back, LB / RB tabs, Start = open and close (`menu.json input`, `MenuUI.cs:130-170`). Loot screen: Start toggles, B closes, A equips (`loot_ui.json:36-39`). Market: X interact, A confirm, B / Start close.
* Prompts: `DirectionPrompt` shows pad wording (RB, LB, right stick) when a pad is present at that moment; the Controls tab shows a Gamepad column; `hud.json hint` rows mix keys and "pad RB / pad LB" in one list.

**Missing / wrong (ranked by what a pad player meets):**
1. **Pad Start opens TWO things.** `menu.json` openKeys and closeKeys contain `JoystickButton7`; `loot_ui.json:36` toggle also contains `JoystickButton7`. `LootScreen.CanOpen` (`LootScreen.cs:36-45`) does not look at `MenuUI`, and MenuUI (order -450) opens first, so outside a live fight (hub, walking in the world between creatures, after a kill) one press can open the pause menu and the equip screen together. UNPROVEN, needs a pad; grep finds no reference to `MenuUI` anywhere in the Loot folder. CODE `lootpad` + DATA `f5loot`. Product question left open: with the toggle blocked while the menu owns the press, a pad player needs another way to the equip screen (all ten face / shoulder buttons are taken: A dodge, B riposte, X/Y specials, LB guard, RB strike, Back potion, Start pause, L3 run, R3 lock).
2. **D-pad does not move in menus.** MenuUI reads only `axisX/axisY` (left stick) and key lists; the D-pad is the separate axes `DPadX/DPadY`. Left stick works, D-pad does nothing. CODE `dpadnav` + the two keys in `f5menu`.
3. **No pad rebinding** (buttons fixed by design). **No pad-specific hint panel**: F1 is keyboard only and every pad button is used, so a pad-only player cannot open the F1 CONTROLS panel; the pause > Controls tab has the pad column and is the substitute. The corner text "F1  Controls" shows to pad players.
4. D-pad Y sign: `pad_extras.json` says up = +1 on Windows XInput; flipped on some pads (note in the file). Never tested on a real pad (pool\ALPHA_item6 G6, still true).
5. Pad hot-plug: the kbm / pad wording is decided once when the prompt starts.
6. Vibration: none.
